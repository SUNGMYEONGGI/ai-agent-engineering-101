4. 다음에 할 수 있는 것과 약점

더 가져올 만한 것

  • USER.md 방식의 CUSTOMERS 섹션 Hermes
    손님은 기억이 있고 포럼을 읽습니다. 단골의 선호와 지난 거래를 memory에 따로 남기면 재방문에 유리합니다.
  • hook 대신 테스트로 막기 Claude Code
    pay_guard 말고 다른 도구 코드에 kit.pay가 있으면 forge 테스트가 실패하게 하라고 goal에 적습니다. 진짜 hook은 아니지만 실수를 한 번 더 걸러 줍니다.

지금 구조의 약점

  • memory 정리를 강제하는 코드가 없습니다. 모델이 memory를 만들지 않거나 부르지 않으면 notes.md가 길어지고, 프롬프트에는 마지막 3000자만 들어가서 오래된 RULES가 잘립니다.
  • pay_guard만 송금한다는 것도 약속입니다. Round 4가 열리면 logs/forge.jsonl에서 memory, pay_guard가 만들어졌는지, notes.md가 2,500자 안인지 사람이 확인해야 합니다.
